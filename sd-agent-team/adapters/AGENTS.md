# AGENTS.md — SD Agent Team 通用接入适配器

> 放到你的项目根目录（或全局配置位置），本文件会被 Codex / OpenCode / ZCode 等支持 AGENTS.md 约定的 Agent 工具自动读取。
> 前提：本仓库根目录下存在 `sd-agent-team/` 目录。

## 研发流程约定（强制，非建议）

本项目的研发工作遵循 `sd-agent-team/` 定义的多阶段流水线。**开始任何研发任务前，必须先完成以下动作：**

1. 读 `sd-agent-team/00-orchestrator/SKILL.md`，按其中「自动衔接协议」确定当前该执行哪个阶段。
2. 若项目 `docs/00-pipeline.md` 存在 → 从其记录的阶段续跑；不存在 → 这是新项目，从阶段 1（需求）开始。
3. 每个阶段执行前，先读该阶段 Agent 的 SKILL.md（`sd-agent-team/0X-xxx/SKILL.md`），严格按其职责、出口检查清单和红线执行。
4. 阶段产出写入项目 `docs/` 目录（PRD→01、原型→02、架构→03、任务→04、实现日志→05、测试报告→06、发布→07、缺陷→08），模板在 `sd-agent-team/templates/`。
5. 阶段完成后按编排器的衔接规则自动进入下一阶段；唯一停顿点是终验。
6. 若项目 `docs/notify.yaml` 存在，按 `sd-agent-team/08-notifier/SKILL.md` 在关键节点推送通知。

## 角色切换方式

你没有多个子 Agent 时（单 Agent 工具），由你自身按阶段切换角色：进入某阶段就把自己当作该阶段 Agent（以其 SKILL.md 为行为准则），完成出口检查后切换到下一阶段角色。

## 红线（与编排器一致）

- 除终验外，任何阶段不得停下等待人工确认
- 质检清单不合格必须自动修订重查，循环有上限（自检 ≤2 轮、测试打回 ≤3 轮、修复迭代 ≤3 轮），超限即停并上报
- 所有判定以 docs/ 交接物文件为准，不依赖对话记忆
